# ⚡ Aftershock: Operationalizing Data Lineage to Eradicate "Action Debt"

## The Problem: The "Action Debt" Gap

When data pipelines break silently, current observability tools stop at the analytical layer—alerting data engineers but ignoring downstream automated systems that may already be consuming the bad data. Fixing a corrupted pricing table does not cancel erroneous purchase orders generated by an automated purchasing agent. We call this unattended operational fallout **Action Debt**.

## The Solution: Active Lineage Remediation

Aftershock transforms DataHub from a passive metadata catalog into an active incident-response platform.

By receiving critical DataHub incident webhooks, Aftershock traverses the downstream lineage graph, identifies operational systems exposed through that lineage, and invokes their predefined compensating controls. Those controls can isolate affected ML models, pause orchestration jobs, or trigger bulk-remediation APIs before the operational damage scales.

## Architecture

1. **Lineage Listener (FastAPI):** Receives `CRITICAL` data-quality incident payloads from a DataHub Actions webhook.
2. **Blast Radius Mapper:** Queries DataHub GraphQL for downstream entities exposed to the corrupted root dataset, with a deterministic local fixture for offline demonstrations.
3. **Compensating Action Engine:** Concurrently invokes state-reversing HTTP playbooks registered on affected downstream systems.

```text
DataHub incident webhook
          │
          ▼
  Lineage Listener
          │ dataset URN
          ▼
 Blast Radius Mapper ──────► DataHub GraphQL lineage
          │ actionable downstream systems
          ▼
Compensating Action Engine ─► Registered remediation APIs
```

## Current MVP Boundary

The MVP proves **system-level remediation**:

```text
corrupted dataset → exposed downstream system → compensating API
```

It does not claim row-level causality or identify individual transactions that consumed corrupted records.

## Future Work: The Action-Provenance Ledger

The next architectural upgrade is an **Action-Provenance Ledger** linking incident windows to exact transaction IDs. This would let Aftershock pass affected order numbers into remediation payloads for surgical transaction reversal without taking an entire downstream agent offline.

python -m pytest -q

python src\demo_dashboard.py

## Connecting a Live DataHub Instance

Without configuration, the mapper uses `mock-data/datahub_lineage.json` for a deterministic offline demo. To query a running DataHub GMS instance, set its base URL; Aftershock posts its lineage query to `/api/graphql`.

```powershell
$env:DATAHUB_GMS_URL = "http://localhost:8080"
```

Start the webhook listener with:

```powershell
python -m uvicorn lineage_listener:app --app-dir src --port 8000
```
